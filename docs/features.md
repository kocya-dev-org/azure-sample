# 機能仕様

> MVP の仕様です。進捗は [MVP チェックリスト](../plan/01-mvp-checklist.md) を確認してください。範囲の判断は [ADR 0003](../plan/decisions/0003-mvp-scope.md) にあります。

## 概要

ソフトウェア製品への要望を入力すると、生成 AI がスコアリングします。指定した期間の要望のうち上位 10 件を、次期開発のバックログとして表示する SaaS です。プロダクトの進化のサイクルを速めるための業務支援サービスを想定しています。

| 利用者                     | 主な操作                                           |
| -------------------------- | -------------------------------------------------- |
| 営業、技術営業、企画の担当 | 顧客から聞いた要望や自身の企画を「提案」として入力 |
| 開発の担当                 | プロダクト情報の登録、バックログの作成と確認       |

優先度: Must は Phase 1、Want は Phase 2 で実装します。

## 画面構成

- **ヘッダー**（Must）: 画面上部に表示し、右端にプロダクト選択リストを置きます。選択した値はブラウザー（localStorage）に保存し、次回も同じプロダクトを選択した状態で開きます。
- **テーマ切り替え**: ヘッダーの右端で、ライト・ダーク・システム設定に合わせる、の 3 つから選べます。既定はシステム設定に合わせる、です。選択はブラウザー（localStorage）に保存します。
- **左メニュー**（Must）: 上から「ダッシュボード」「提案」「バックログ」「プロダクト情報」の順に、アイコン付きで並べます。狭い画面では、ヘッダーのメニューボタンから開きます。
- **コンテンツ領域**: ヘッダーとメニュー以外の領域です。
- プロダクトを選択していないときは、提案とバックログの画面にプロダクトの選択を促すメッセージを表示します。
- 削除などの取り消せない操作は、確認ダイアログで確かめてから実行します。登録・保存・削除・状況の変更・Issue 起票の結果は、画面右上のトーストで知らせます。

| パス                  | 画面                 | 優先度 |
| --------------------- | -------------------- | ------ |
| `/`                   | ダッシュボード       | Want   |
| `/proposals`          | 提案一覧             | Must   |
| `/proposals/new`      | 提案フォーム（新規） | Must   |
| `/proposals/:id/edit` | 提案フォーム（編集） | Must   |
| `/backlogs`           | バックログ一覧       | Must   |
| `/backlogs/:id`       | バックログ詳細       | Must   |
| `/products`           | プロダクト情報       | Must   |

## 提案

### 提案一覧（Must）

- 選択中のプロダクトの提案を、カード表示またはリスト表示で並べます。
  - 画面右上のトグルアイコンで切り替えます。既定はカード表示です。
  - 選んだ表示はブラウザーに保存し、次に開いたときも同じ表示にします。
  - 表示を切り替えても、チェックボックスの選択は保ちます。
- カード表示では、1 件ずつカードにして並べます。カードには選択チェックボックス・タイトル・投稿者・登録日・RICE スコア・戦略合致度と、本文の冒頭 50 文字（改行は空白にまとめ、超えた分は「…」で省略）を表示します。
- カードの幅は固定（20rem）です。画面が広いほど横に並ぶ枚数が増えます（このページだけ本文の最大幅を制限しません）。狭い画面では 1 列になります。
- リスト表示では、表の 1 行に 1 件を表示します。
  - 列は選択チェックボックス・タイトル・投稿者・登録日・RICE スコア・戦略合致度・操作アイコンです。
  - タイトルの下に、カードと同じ本文の冒頭 50 文字を表示します。
- カード右下、またはリストの行末のアイコンで、その提案を操作します。
  - 鉛筆（編集）: 提案フォーム（編集）に移ります。
  - ゴミ箱（削除）: 確認ダイアログの後、その提案と、そのスコア付き項目を削除します。
- 上部の操作は次のとおりです。
  - 「すべて選択」: すべての提案のチェックボックスを切り替えます。
  - 「削除」: 1 件以上を選んだときに有効です。確認ダイアログの後、選んだ提案と、そのスコア付き項目をまとめて削除します。
  - 「新規登録」: 提案フォーム（新規）に移ります。

### 提案フォーム（Must）

1. 「タイトル」と「内容」を入力し、「判定」を押します。
2. 生成 AI のコメントが、ストリームで少しずつ表示されます。AI は RICE の 4 要素（Reach、Impact、Confidence、Effort）それぞれについて、判断に必要な情報があるかを確認し、足りない情報を箇条書きで質問します。
   - コメントと並行して、提案の内容が**いまのアプリにすでに実装されているか**を生成 AI が確認します（[ADR 0012](../plan/decisions/0012-implementation-check-copilot-spaces.md)）。根拠は GitHub Copilot Space `kocya-dev-org/spaces-azure-sample` の内容です。
   - 結果はコメントの下の「実装状況」欄に表示します。確認中はスピナーを表示し、届いたら「実装済み」「一部実装済み」「未実装」「確認できませんでした」のバッジと説明を表示します。
   - 説明は、コードを知らない利用者向けに、どの画面の、どのボタンや項目で、どのように使えるかを書きます（一部実装済みなら、できることとまだできないことを分けます）。
   - 確認に失敗しても、コメントと送信はそのまま使えます（「確認できませんでした」と表示します）。結果は保存しません。
3. コメントの表示が終わったら、次のどちらかを選びます。
   - 「このまま送信」: 4 に進みます。
   - 「追記して再判定」: 内容を書き足してから、もう一度「判定」を押します（2 に戻ります）。
4. 送信するとスコアリングが行われ、処理中は表示を出します。完了すると提案一覧に戻ります。

- 編集の場合も同じ流れで、送信すると判定とスコアリングをやり直します。
- **音声入力**（Should）: 「内容」の右上の「音声で入力」で録音できます（[ADR 0011](../plan/decisions/0011-voice-input-transcription.md)）。
  - 初回はブラウザーがマイクの使用許可を求めます。
  - 録音中は「停止」ボタンに経過時間を表示し、最大 90 秒で自動的に止まります。
  - 止めると生成 AI が文字起こしし、結果を「内容」の末尾に改行して追記します。8000 文字を超えた分は切ります。
  - 録音中と文字起こし中は「判定」を押せません。追記された内容は、ほかの入力と同じく編集してから判定に進めます。
  - 音声はどこにも保存しません。
  - 録音に対応していないブラウザーでは、ボタンを表示しません。マイクの使用が拒否された場合や、文字起こしに失敗した場合は、フォームにエラーを表示します。
- 投稿者は、ログインしているユーザーの情報からサーバー側で設定します。

### スコアリング

送信時に、生成 AI を 1 回呼び出して RICE の各値と戦略合致度を求めます。

**RICE**（Must）

| 要素       | 定義                                 | 取りうる値         |
| ---------- | ------------------------------------ | ------------------ |
| Reach      | 四半期あたりに影響を受けるユーザー数 | 0 以上の整数       |
| Impact     | 影響の大きさ                         | 0.25, 0.5, 1, 2, 3 |
| Confidence | 見積もりの確度                       | 0.5, 0.8, 1.0      |
| Effort     | 必要な工数（人月）                   | 0 より大きい値     |

- RICE スコアは `Reach × Impact × Confidence ÷ Effort` です。
- 生成 AI は各値と根拠を JSON で返します。サーバーは値の範囲を検証してから、スコアを自分で計算します。

**戦略合致度**（Must）: 提案がプロダクトの戦略（狙い、開発戦略、将来像）に沿っているかを、0〜100 の整数と根拠で評価します。

## バックログ

### バックログ一覧（Must）

- 作成済みのバックログを一覧表示します。列は期間・作成日・件数です。行をクリックすると、バックログ詳細に移ります。
- 上部の「作成」を押すと、期間（開始日と終了日）の入力欄と「作成」ボタンだけのダイアログを出します。作成すると、そのバックログの詳細画面に自動で移ります。

### バックログの作成規則

- 選択中のプロダクトで、提案の登録日が指定期間（日本時間の日付。開始日と終了日を含む）に入るスコア付き項目を対象にします。作成ダイアログの初期値は、直近 30 日間です。
- RICE スコアの降順に並べ、同じ値なら戦略合致度の降順にして、上位 10 件を選びます。
- 作成した時点の順位とスコアを、スナップショットとして保存します。後から提案を編集しても、作成済みのバックログの順位とスコアは変わりません。

### バックログ詳細（Must）

- 順位・項目名・RICE スコア・戦略合致度を表示します。行を展開すると、スコアの根拠（RICE の各値と理由、戦略合致度の理由）を確認できます。
- Phase 2 では次を追加します。
  - 各行の実装状況（未対応 / 実装済み）の切り替え（Want）。実装状況は項目ごとに 1 つで、同じ項目を含むすべてのバックログに反映されます。
  - 各行のチェックボックスと、上部の「Issue 起票」ボタン（Want）。選んだ項目を、プロダクトの GitHub リポジトリに Issue として登録します。起票済みの項目には Issue へのリンクを表示し、再度は起票しません。
  - GitHub 連携が未設定のとき、またはプロダクトにリポジトリが登録されていないときは、「Issue 起票」と「Issue 状態を更新」のボタンを無効にし、その理由を表示します。
  - Issue の状態の反映（Want）: 起票済みで未対応の項目について GitHub Issue の状態を確認し、Issue が完了（`state_reason` が `completed`、または理由なし）で閉じられていれば実装済みにします。
    - 確認は 2 通りで行い、処理の内容は同じです。
      - 毎日 1 回（日本時間 3:00）、全プロダクトを自動で確認します。
      - バックログ詳細画面の「Issue 状態を更新」ボタンで、選択中のプロダクトを手動で確認します。
    - 「対応しない（not planned）」や「重複（duplicate）」で閉じられた Issue の項目は、未対応のままにします。
    - 実装済みにした日（`doneAt`）は、Issue が閉じられた日時にします。
    - 実装済みから未対応へは自動で戻しません。Issue を再オープンした場合も同じです。
    - 実装済みの項目には触れません。ただし、Issue が完了で閉じたまま手動で未対応へ戻すと、次回の確認で再び実装済みになります。

## プロダクト情報（Must）

- プロダクトの一覧（名前・リポジトリ・更新日）を表示します。行を選ぶと編集ダイアログが開きます。
- 上部の「新規登録」で、新規登録ダイアログを開きます。
- ダイアログの入力欄は次のとおりです。

  | 項目       | 必須 | 内容                                         |
  | ---------- | ---- | -------------------------------------------- |
  | 名前       | ○    | プロダクト名                                 |
  | 戦略       | ○    | 狙い、開発戦略、将来像など（複数行テキスト） |
  | リポジトリ | —    | GitHub の `org/repository` 形式（Want）      |

- リポジトリ欄は Phase 1 から入力できます。Issue 起票（Phase 2）で使います。
- 削除は編集ダイアログで行います。紐づく提案、スコア付き項目、バックログもまとめて削除されることを、確認ダイアログで伝えます。

## ダッシュボード（Want）

- 選択中のプロダクトの提案数・Issue 起票数・実装済み数をカードで表示します。
- 月は日本時間で区切ります。提案は登録日、Issue は起票日、実装済みは実装済みにした日の月に数えます。
- 月ごとの提案数・Issue 起票数・実装済み数の推移（直近 6 か月）を、棒グラフで表示します。グラフは shadcn/ui の Chart（Recharts）で描き、月にポインターを合わせると値をツールチップで表示します。同じ数値を表でも表示します。
